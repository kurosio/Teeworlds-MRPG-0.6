# Editor Studio • Core guide

## Цель
- Единый UI/стили для всех редакторов.
- Один набор компонентов + утилит в `editor-core/`.
- Минимум копипасты при создании нового редактора.

## Что использовать
### 1) Подключение Core
Рекомендуемый вариант (единый набор модулей + порядок в одном месте):

```html
<script src="editor-core/page-loader.js"></script>
```

Лоадер подключает локальные стили и все модули `editor-core` слоями (основа →
справочники → каркас → данные → страница) и последним шагом вызывает
`EditorCore.bootstrapEditor()`. Это единственная точка входа общей обвязки:
функция идемпотентна, аргументов не принимает и при повторном вызове отдаёт
тот же объект, поэтому страница может звать её без опаски. Отдельного
глобального алиаса (`window.EditorCoreBootstrap`) нет: глобус-дубль только
путал, какой из двух вызовов «настоящий». Ошибка инициализации попадает в
консоль и уведомление, а не в необработанное исключение.

### 2) Быстрый старт страницы

```js
const { fieldRenderOptions } = EditorCore.bootstrapEditor();
```

Одна строка даёт общий набор классов для полей. Своих копий классов и
«режимов» (`event`, `scenario`) нет: профиль отрисовки в ядре один, поэтому и
аргумента у `EditorCore.defaults.getFieldRenderOptions()` нет.

### 3) Формы из схемы (рекомендуется)
Если редактор — это "форма по схеме", используйте `EditorCore.FormRuntime`:

```js
const form = EditorCore.FormRuntime.mount(root, {
  fields: schemaFields,
  data: model,
  fieldOptions: fieldRenderOptions,
  onChange: (data, { path, value }) => { /* ... */ }
});
```

`FormRuntime` + `FieldRenderer` дают:
- единые поля, валидацию, toggles
- `db_select` и `db_multiselect` (авто-подгрузка из БД)
- списки с add/remove и сохранением `itemDefault`
- `form.validate({ focus: true })` перед сохранением; `form.destroy()` при закрытии редактора

Правила `validate` задают `required`, `min`, `max`, `integer`, `pattern` и тексты
ошибок. Пустое необязательное поле допустимо, число `0` не считается пустым.
Скрытые и отключённые поля не блокируют сохранение. Ошибки получают связанный
`aria-describedby`/подсказку; повторный `mount` или `setData` не накапливает
обработчики и по возможности сохраняет фокус и позицию курсора.

## Быстрый CRUD-редактор (DB)
Для стандартных таблиц (list + форма + сохранение) используйте `EditorCore.DbEditor`:

```js
const { fieldRenderOptions } = window.EditorCoreBootstrap || EditorCore.bootstrapEditor();

const editor = EditorCore.DbEditor.mount(document.body, {
  resource: 'worlds',
  fields: schemaFields,
  fieldOptions: fieldRenderOptions,
  defaults: () => ({ Name: '', Path: '', Type: 'default' }),
  rowToModel: (row) => ({ ...row }),
  modelToPayload: (model) => ({ ...model })
});
```

Такой runtime уже решает:
- загрузку списка, поиск, выбор записи
- валидацию и сохранение / удаление с блокировкой повторной операции
- стабильный снимок данных и ID на время запроса; устаревший ответ не меняет новую запись
- отмену поиска и загрузок справочников при смене формы
- единый адаптивный макет (через `editor-template.css`)

`await editor.ready` дожидается первой загрузки. `editor.destroy()` освобождает
обработчики, таймеры и форму; повторное монтирование на том же корне сначала
закрывает предыдущий runtime. Форматы строк БД и маршруты гостевых черновиков
при этом не меняются.

### Сеть и отмена

`EditorCore.Http.json/text/request` принимают `timeout` (мс; по умолчанию 15000)
и `signal` от `AbortController`. Таймаут охватывает получение CSRF, запрос и чтение
тела; отменённая запись не повторяется после обновления CSRF. Для параллельных
запросов обновление токена общее, но отмена одного вызова не отменяет остальных.
`json` возвращает `{ ok, status, error, data, cancelled, retryAfter }`; `request`
при ошибке бросает исключение с теми же метаданными. Тело Studio API — JSON-строка
или обычный объект; заголовки можно передавать объектом или `Headers`.

### Проверки

Из `web-tools/editor-studio`: `npm test`, `npm run check`, `npm run test:php`,
`npm run test:store`. Последние два скрипта используют опциональные PHP WASM
пакеты; установка описана в `STRUCTURE.md`. `npm run test:browser` запускает
локальный сценарий Chromium без подключения к игровой БД.

## Несохранённые правки: подсказка, уход со страницы, оболочка

Три вещи нужны каждому редактору, поэтому они живут в ядре, а не в странице:

```js
// 1. Плашка «Data not saved» + предупреждение браузера при закрытии вкладки.
//    Автопрослушка ввода/кликов внутри root помечает правки сама.
const dirty = EditorCore.Dirty.create({
  root: document.querySelector('.editor-main') || document.body,
  pill: document.getElementById('dirty-pill'),
  beforeUnload: true,
});
dirty.markDirty();
dirty.setClean();

// 2. Ответ оболочке студии: она спрашивает, можно ли закрыть вкладку.
EditorCore.Dirty.bindShellStatus(() => dirty.isDirty());

// 3. Подтверждение перед переключением на другую запись.
if (!await EditorCore.Page.confirmDiscard(() => dirty.isDirty())) return;
```

`beforeUnload: true` заменяет `Page.guardUnsaved`: страховка браузера живёт в том
же трекере. `Page.guardUnsaved` остаётся для редакторов со своим счётчиком
правок, где общего трекера нет; заводить оба на одну страницу не нужно.

`bindShellStatus` сам проверяет источник сообщения и формат ответа: странице не
нужно знать про `postMessage`. Если редактор считается «грязным» ещё и во время
операции, это просто добавляется в переданную функцию.

## DB Select (db_select)
- В схеме поля указывайте `ui.dbKey` (предпочтительно) или `ui.datasource`.

Пример:
```js
QuestID: { type: 'db_select', label: 'Квест', ui: { dbKey: 'quest' }, validate: { required: true } }
```

Карта ключей хранится в `editor-core/db-map.js`.

## Tags (теги / chips)

Универсальный виджет для полей типа `SET`/массивов (строки) и для списков ID (из БД).

**Возможности:**
- поиск по вариантам
- добавление/удаление кликом
- клавиатура: ↑/↓ выбор, Enter добавить, Backspace удалить последний
- адаптивная сетка вариантов (на широких экранах несколько колонок)

### 1) Статический список (ручные варианты)

```js
Debuffs: {
  type: 'set',
  label: 'Debuffs',
  ui: EditorCore.presets.tags({
    options: ['Slowdown', 'Poison', 'Fire'],
    placeholder: 'Добавить debuff...'
  })
}
```

### 2) Варианты из БД (храним массив ID)

```js
DropItems: {
  type: 'array',
  label: 'Дроп: предметы',
  ui: EditorCore.presets.tags({
    datasource: 'item',   // DBMap key (или прямой source, например 'items')
    valueType: 'number',  // значения будут числами
    labelMode: 'id_name', // 'name' | 'id_name'
    placeholder: 'Добавить предмет...'
  })
}
```

## PositionPicker (позиция на карте)

Один элемент для всех координат: карточка закреплённой точки, мир, кнопка карты
и кнопка ручного ввода. X/Y хранятся в скрытых инпутах, поэтому `FormRuntime`,
валидация и гостевые правки работают как обычно.

**Через схему (рекомендуется):**

```js
Position: {
  type: 'vec2',
  label: 'Позиция на карте',
  ui: { step: 1, mapWorldPath: 'WorldID' }
}
```

- `mapWorldPath` связывает подложку «Мир» с существующим полем формы: выбор
  мира в карточке или в окне карты сохранится в `WorldID`.
- `ui.axes: { x: 'PosX', y: 'PosY' }` — для двух отдельных колонок БД.
- `ui.map: false` / `ui.world: false` скрывают соответствующие действия.

### Флаги карты

Флаги задаются в `ui` (или в `PositionPicker.render()`) и попадают в окно карты
через `PointMap.open()`. Активные флаги видны в карточке как короткие метки —
сразу понятно, с каким набором слоёв откроется карта. Настройки `safeTiles`, `showTiles`,
`highlightTiles`, `linkedTiles`, `radii`, `grid` и `snap` задаются на каждом `vec2`
отдельно; сохранённое пользователем переключение привязки также изолировано по
`mapPickerTag` и путям координат и не переносится случайно в другой редактор.

| Флаг | Что делает | Где используется |
| --- | --- | --- |
| `safeTiles: true` | Запрещает COLLIDE(1)/DEATH(2)/UNHOOK(3): точка на них не применяется, но **не сбрасывается** | мобы, NPC, позиция шага и цели заданий |
| `safeTiles: [2, 3]` или `blockTiles: [2]` | Свой список запрещённых ID тайлов | точечные сценарии |
| `showTiles: true` | Включить игровой слой при открытии, без запрета размещения | аэтры, подземелья, склады, телепорт сценария |
| `highlightTiles: [209]` | Подсветить перечисленные ID тайлов; [] отключает подсветку. ID — настоящие индексы `.map`: 209 — спавн мобов (не «Кости казино», это 242) | позиции мобов, компонент defeat_mobs |
| `highlightLayer: 'game'` | К какому слою относятся ID из `highlightTiles`. Обязателен, если подсвечиваются 199/200/201: они есть и в игровом слое (метки узлов сбора), и как типы switch-слоя | мобы, аэтры, склады, доски квестов, сценарии |
| `linkedTiles: true` | В секции «Точки на карте» показать существующие координаты подсвеченных тайлов и включить редактор точек (добавление, перенос, удаление, switch-слой). Если совпадений нет, список пуст, но обычный выбор позиции остаётся доступен | точки спавна мобов, доски квестов, склады, аэтры и другие сущности, привязанные к тайлам карты |
| `radii: [{ path: 'Radius', label: 'Spawn radius', color: '#52df9a', dash: [6, 4] }]` | Массив окружностей: у каждой свой радиус (поле формы `path` или фиксированный `value`), цвет линии, штрихи пунктира (`[]` — сплошная), толщина и подпись | мобы (радиус спавна + активности), сценарий `defeat_mobs` |
| `radii: [{ value: 320, label: 'Action radius', ... }]` | Фиксированный радиус без поля формы — для дистанций, зашитых в сервер (склад, аэтр, доска квестов) | склады, аэтры, доски квестов |
| `grid: true` | Включить сетку 32×32 при открытии | мобы, NPC, задания, двери подземелий |
| `snap: true` | Включить привязку к центрам тайлов при открытии | мобы, NPC, задания, двери подземелий |

Радиусы объявляются **только** массивом `radii`. Одиночные ключи `radiusPath`,
`activeRadiusPath`, `radius` и `radiusActive` удалены из конфига: старые
объявления нужно переписать на `radii` (по одному элементу на окружность),
иначе окно карты просто не нарисует круг.

Окно карты состоит из трёх уровней: шапка (точка и камера), панель
**«Инструменты карты»** и подвал с X/Y и кнопками «Применить / Отмена».
На телефоне панель становится листом во всю ширину между шапкой и подвалом
(её высоту считает `picker.js` по реальным размерам шапки и подвала), тело
секций прокручивается внутри, а кнопки «Применить / Отмена» и предупреждение
о запрещённом тайле всегда остаются на виду.
В панели один переключатель **«Клик по карте»** — *Ставит точку · Ставит тайл ·
Измеряет* — и отдельные секции. Поэтому клик по карте всегда означает ровно
одно, а инструменты не спорят друг с другом:

- **Настройки точки** (свёрнуты) — сетка, привязка к центрам тайлов, «В центр
  тайла», история отмены, «Исходная точка», копирование X/Y.
- **Существующие точки** (`linkedTiles: true` + `highlightTiles`) — список
  координат уже стоящих на карте тайлов, **«Использовать точку»** переносит
  выбранную в запись.
- **Правка точек и switch-тайлов** (непустой `highlightTiles`) — полный
  редактор точек карты, но правится **только объявленное**: список ID в
  игровом слое и список типов в switch-слое собираются из `highlightTiles`.
  Слой без объявленных ID недоступен; если объявлений нет вовсе, остаётся
  только установка позиции. В игровом слое это сущности (192–198 пикапы,
  стены ботов и метки ресурсов, 208/209/211 спавны, 241–243 ритм-поле и
  казино), в switch-слое — объявленные типы (199
  растения, 200 руда, 201 рыба, зоны 22–25) и **любой номер switch 1–255**,
  как в редакторе узлов сбора. Клик по пустой клетке ставит точку, по занятой — выделяет её;
  выбранную точку можно перенести перетаскиванием, удалить (`Delete`) или
  вернуть к исходному виду. Вода, зоны и стены клеткой правки не считаются:
  клик по ним объясняет, что это геометрия карты, а клик по необъявленному ID —
  что он не входит в `highlightTiles`. Клавиши `1`/`2`
  переключают слой, `R` сбрасывает черновик, `Esc` при несохранённых правках
  спрашивает подтверждение. Тайлы столкновений 1–3 не правятся, а у
  switch-тайла меняется только номер и тип — флаги и задержка остаются как в
  карте. Черновик сверяется с живой картой: при расхождении «Применить»
  блокируется, а не перезаписывает чужие правки.
- **Видимость карты** — игровой слой `.map` и переход камеры к спавну.
- **Замер расстояния** — `M`, длина/тайлы/ΔX/ΔY, «B → позиция».
- **Предпросмотр радиуса** — дополнительная окружность, поле записи не меняется.
- **Слои оформления** — скрытие фоновых и передних слоёв в этом окне.

Без `showTiles: true` игровой слой выключен, без `grid: true` выключена сетка;
`safeTiles`, `highlightTiles`, `linkedTiles` и `radii` не меняют эти начальные
состояния и не раскрывают панель. `linkedTiles: true` использует ID из
`highlightTiles`: список выбираемых позиций строится по игровому слою карты,
каждая координата соответствует центру тайла. Если в карте ещё нет ни одного ID
из `highlightTiles`, переключатель установки недоступен: карту нельзя
использовать для создания первой такой точки, но X/Y выбираются обычным кликом.
Любая правка точки сначала остаётся черновиком. «Применить» атомарно сохраняет
оба слоя (игровой и switch) и координаты, «Отмена» отбрасывает черновик.
Сервер принимает добавление, перенос и удаление только для сущностей из
`X-Map-Allowed-Tiles` и не даёт менять структуру карты, флаги клеток и прочие
ресурсы. Запись карты доступна только
администратору и только для локального файла с правом записи; перед изменением
создаётся резервная копия. Удалённые карты через map-api остаются только для
чтения. Запущенный игровой сервер применит файл при следующей загрузке этого
мира. Например, `ui: { showTiles: true, grid: true }` включает оба инструмента
для конкретного `vec2`, а пустой `ui: {}` оставляет оба выключенными. Сетка не
восстанавливается из прошлого посещения карты.

Пример для моба:

```js
Position: {
  type: 'vec2', label: 'Позиция (X, Y)',
  ui: {
    axes: { x: 'PositionX', y: 'PositionY' }, mapWorldPath: 'WorldID',
    safeTiles: true, highlightTiles: [209], linkedTiles: true,
    // Радиус спавна — зелёный, радиус активности — синий: цвет, пунктир и
    // подпись задаются здесь, поэтому на карте не бывает «безымянных» кругов.
    radii: [
      { path: 'Radius', label: 'Spawn radius', color: '#52df9a', dash: [6, 4] },
      { path: 'ActiveRadius', label: 'Active radius', color: '#6f8cff', dash: [3, 3], lineWidth: 1.5 }
    ],
    grid: true, snap: true
  }
}
```

Точка на запрещённом тайле остаётся в скрытых X/Y: `editor-map:validity`
лишь подсвечивает карточку (`is-invalid`), а «Применить» в карте блокируется,
пока точку не перенесут. Ручной ввод координат работает всегда — это путь
исправить значение, если карта мира недоступна.

**Программно (кастомные редакторы):**

```js
const picker = EditorCore.PositionPicker.create({
  label: 'Точка цели',
  xPath: 'move_to.0.x',
  yPath: 'move_to.0.y',
  worldPath: 'move_to.0.world_id',
  worldId: 0,
  step: 1,
  compact: true,
  safeTiles: true,
  xInputHtml: '<input type="number" data-position-axis="x" data-map-axis="x" ... hidden>',
  yInputHtml: '<input type="number" data-position-axis="y" data-map-axis="y" ... hidden>',
});
host.appendChild(picker);

EditorCore.PositionPicker.onWorldChange(picker, (worldId) => saveWorld(worldId));
EditorCore.PositionPicker.setWorldId(picker, 3);
EditorCore.PositionPicker.openMap(picker, { worldId: 3, mapOptions: { safe: [1, 2, 3] } });
EditorCore.PositionPicker.setValue(picker, { x: 100, y: 200 });
EditorCore.PositionPicker.getMapOptions(picker); // флаги, с которыми создан элемент
```

Элемент сам подписывается на `editor-map:applied`, `editor-map:world`,
`editor-map:validity` и `editor-map:closed`, поэтому выбранные в карте точка,
мир и состояние валидности возвращаются в форму без дополнительного кода.

Архитектура: `PositionPicker` — единственный UI-элемент и единственная точка
открытия карты (`PointMap.open()`). `PointMap` — только диалог с iframe; он не
ищет поля мира и не грузит БД. Общий кэш списка миров, парсинг ID (включая мир
0) и «последний выбранный мир» живут в `editor-core/map-worlds.js`. Кнопку
карты обрабатывает сам элемент — второго глобального слушателя кликов нет.

## Карта модулей ядра

Модуль — одна обязанность. Если что-то хочется скопировать из страницы в
страницу, место нового помощника — в этом списке, а не в третьей копии.

| Слой | Модули | За что отвечают |
| --- | --- | --- |
| Основа | `http.js`, `utils.js`, `tailwind-theme.js` | запросы и CSRF, общие утилиты (экранирование, числа, пути, грязные правки), тёмная тема |
| Справочники | `reference-data.js`, `guest-mode.js`, `change-markers.js`, `request-context.js`, `deep-link.js` | значения из БД, гостевые правки, пометки изменённых полей, контекст запроса, переходы по ссылке `?record=` |
| Каркас | `registry.js`, `core.js`, `field-renderer.js`, `dependent-select.js`, `form-runtime.js`, `dialog-editor.js` | реестры, фабрика приложения, поля из схемы, связанные селекты, формы, диалоги |

## Правила страницы (их проверяет `tools/check.mjs`)

Страница не заводит своё там, где есть общий инструмент:

```js
const $ = EditorCore.Page.byId;              // вместо (id) => document.getElementById(id)
const esc = EditorCore.Page.esc;             // вместо своей функции экранирования
const { fieldRenderOptions } = EditorCore.bootstrapEditor();
const dirty = EditorCore.Dirty.create({ pill, beforeUnload: true }); // без ?.create и заглушек
const id = EditorCore.utils.toPositiveInt(value);   // «ID или null»
const number = EditorCore.utils.toPositiveNumber(value);
```

Линтер падает, если в странице снова появятся:

- `window.EditorCoreBootstrap` или `bootstrapEditor({ mode })` — режимов нет;
- `EditorCore.Dirty?.create` с самодельной заглушкой;
- своя функция экранирования HTML;
- `data-mode` на теге `page-loader.js` (атрибут никто не читал);
- свой обработчик `editor-shell:dirty-status` или своё подтверждение потери правок.

## Как добавить новый редактор в Studio
1) Создайте файл `my-editor.html`.
2) Добавьте его в `studio.manifest.js` в нужную группу.
3) Используйте набор `editor-core/*.js` + `FormRuntime`.

## Editor Template (layout) — единый адаптивный макет

В `editor-core/editor-template.css` лежит тонкий слой разметки/макета:
- `.editor-page` — общий контейнер страницы
- `.editor-shell` — сетка Sidebar + Main (на мобилке складывается)
- `.editor-section` — секции формы
- `.editor-form-grid-2` — быстрый 2-колоночный грид для форм

Чтобы включить цветовые пресеты, просто поставьте атрибут:

```html
<body class="editor-theme" data-editor="crafts">
```

### Списки как таблица (ровные строки)

Для любых `type:'list'` можно включить режим таблицы:

```js
RequiredItemsArr: {
  type: 'list',
  ui: {
    listMode: 'table',
    tableHeader: ['Предмет', 'Кол-во'],
    tableColsMd: 'minmax(0,1fr) 160px'
  },
  itemFields: { ... }
}
```

Это даёт ровные колонки на десктопе и аккуратный стек на телефоне.
