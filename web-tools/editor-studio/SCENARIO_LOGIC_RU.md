# Логика сценариев

Компоненты в меню добавления разделены по назначению; поиск ищет по всем группам. Доступный набор зависит от режима сценария.

**Универсальное условие** проверяет число участников или живых игроков, количество предметов либо состояние задания. Сравнение, область подсчёта и инверсия позволяют менять смысл проверки. Переходы настраиваются в полях «Переход при выполнении» и «Переход при неудаче или истечении времени» либо на графе.

- По умолчанию условие ждёт выполнения; при тайм-ауте больше нуля оно завершается по ветке неудачи. Ноль означает неограниченное ожидание.
- «Проверить сразу» выполняет одну проверку и выбирает ветку успеха или неудачи без ожидания; тайм-аут игнорируется. Без соответствующего перехода продолжается обычный порядок шагов (или общий `next_step_id`). Старые сценарии без этой опции продолжают ждать как прежде.
- Переход выполняется при завершении **шага**, не мгновенно посреди него. Если несколько компонентов задают переход, выбирается первый по порядку. Чтобы решение было однозначным, удобно выделить его в отдельный шаг. Настройки all/any/sequential и задержка шага по-прежнему влияют на завершение.
- Переходы возможны только внутри одного события; разные события запускаются отдельно. Необязательно заданные ветки продолжают обычный порядок, поэтому разместите ветки и их завершающие переходы явно, чтобы не перейти случайно в соседнюю ветку.

## Примеры

1. **Развилка по ключу.** Универсальное условие: `item_count`, предмет «ключ», `>= 1`, «Проверить сразу». Успех → открытая дверь; неудача → подсказка и конец. Обе ветки могут вести к общему финалу.
2. **Спасение на время.** Проверка `alive_players_count >= 2`, тайм-аут 60 секунд: выполнение → награда, тайм-аут → эвакуация. Условие выигрывает, если выполнено в том же тике, что истёк таймер.
3. **Разные встречи.** Случайная ветка с шансом 30% ведёт к засаде, иначе — к торговцу; затем обе ветки переходят к общему шагу.
4. **Ветвление по заданию.** Проверка завершённого задания с немедленным выбором: опытным игрокам показать короткое сообщение, остальным — обучение.

Для повторного прохождения шага используйте переходы между разными шагами; избегайте бесконечных циклов без ожидания и выхода. Пустое или неверное назначение перехода может закончить сценарий: проверяйте связи на графе и валидацией редактора.
